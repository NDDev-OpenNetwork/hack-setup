# Serena-first source change

Read the root AGENTS and standards index, then SERENA-WORKFLOW and the affected language standard. Resolve repository paths from the current worktree even when this skill is installed globally.

1. Verify the branch/worktree and Serena project identity. Read actual tool schemas and available capabilities.
2. Locate the relevant symbol and inspect its body plus necessary callers/references. Use bounded text search for string-driven contracts or unsupported source areas.
3. Select a precise symbolic edit or a narrow text patch according to the change. Keep generated outputs under their generator.
4. Inspect semantic impact beyond the rename: wire keys, routes, SQL, templates, reflection and clients may require separate changes.
5. Validate with the selected compiler/parser and a targeted behavior check. Report a tooling gap rather than claiming success from no diagnostics.
6. Inspect the diff, preserve unrelated work and provide the factual handoff.

Do not run full indexing or every language server after each tool call. Do not demand manual approval for routine changes within the authorized task. If semantic tooling fails, attempt a bounded repair, then use and disclose the appropriate fallback. This workflow is not permission to create product code before the event.



Observe the actual Codex-context tool inventory rather than assuming Serena exposes generic read/write/shell tools. Inspect current file state before retrying a timed-out edit. Verify index exclusions before interpreting an empty symbol search as absence.

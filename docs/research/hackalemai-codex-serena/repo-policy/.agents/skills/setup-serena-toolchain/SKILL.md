# Configure the development toolchain

Locate the supplied preparation pack and read BOOTSTRAP-PROMPT.md, the compatibility report, installation recipes and acceptance matrix. Do not assume the pack lives in the application repository.

Inventory and back up affected configuration. Preserve provider/auth/skills and authorized permissions. Install a pinned isolated Serena tool environment, then configure one MCP process per worktree and only the required language adapters.

Resolve the native-TypeScript/tsserver distinction, Flutter-Dart analyzer identity, ty path/version and LSP-enabled Taplo. Avoid unsupported keys, main-only commands and blocking reminder hooks.

Merge the compact instruction router and relevant skills. Run actual MCP and semantic behavior acceptance, including Unicode and worktree isolation. Produce an exact host report with NOT-TESTED where evidence is absent.

Do not create product source code or a reusable app scaffold during preparation. Do not call a syntax-checked configuration a fully working integration.



Before selecting a server, consult the preparation pack's historical cutoff and source-evidence ledger. The stable external registry gap, ignored project base_modes, shallow local overrides and hook trust/timeouts require explicit effective-configuration checks. Keep templates unmaterialized until real host paths/versions are known. Do not upgrade Serena silently while claiming the stable baseline.

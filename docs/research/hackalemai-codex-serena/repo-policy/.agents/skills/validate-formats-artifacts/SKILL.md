# Validate the actual format and consumer

Load FORMATS and, for binary/visual output, DOCUMENTS. Add the technology standard for the consumer: INFRA for Compose/Vector/Caddy, CONTRACTS for OpenAPI, NATIVE-MOBILE for ARB, DELIVERY for judged materials.

Identify actual format, encoding, schema and owner tool. Parse or validate with that format's tool. Then validate the real consumer or rendering: valid YAML does not prove a valid deployment; extracted PDF text does not prove correct layout.

Preserve provenance, precision, formulas and placeholders. Reject accidental duplicate keys, unsafe XML expansion or active spreadsheet interpretation of imported text. Do not symbol-rewrite binary documents or entire notebooks.

Render changed pages/slides/UI and inspect legibility/overflow where applicable. Record exactly what was checked and which required engine or platform was unavailable. Never fabricate a completed preview or a successful formula recalculation.



Separate syntax, schema and native-consumer results. Validation must not silently fix or regenerate an artifact. A browser worker running student code is not automatically an origin/credential sandbox.

## Принятые решения

Codex является MCP-клиентом; Serena предоставляет семантическую навигацию и редактирование через SolidLSP; компиляторы, линтеры и специализированные валидаторы подтверждают результат. Это три разных слоя.

Serena-first означает: сначала искать символ, определение и зависимости семантически, когда операция поддерживается. Это не Serena-only: строки, конфиги, документы, отсутствующие символы и неподдерживаемые форматы обрабатываются подходящим текстовым или форматным инструментом.

У каждого разработчика свой worktree и собственный процесс Serena. Состояние активного проекта не разделяется между тремя агентами. Правила проекта являются источником истины; memories Serena лишь помогают навигации и не заменяют инструкции.

Для Python выбран маршрут `python_ty` с согласованной версией `ty`; Pyright служит резервным адаптером. Для TypeScript сохраняется нативный компилятор проекта, но совместимость tsserver-пути Serena проверяется отдельно. Для Flutter версия Dart-анализатора должна соответствовать SDK, а не скрытому старому значению адаптера.

## Что проверено, а что нет

Прочитаны официальные документы Codex, Serena и поставщиков LSP, а также конкретные файлы Serena 1.7.0. Базовый commit Serena: `949a27ef1e5fda1a6e7b561e777bcece345c6ffd`. Для Codex подтверждён опубликованный до базовой даты стабильный релиз 0.155.1.

В этом сеансе **не устанавливались** Codex, Serena и LSP на ваших Mac/VPS; не запускались MCP handshake, индексация проекта, Flutter-анализ и совместная интеграционная сборка. Пакет не объявляет такую совместимость доказанной. Агент должен выполнить [ACCEPTANCE.md](setup/ACCEPTANCE.md), сохранить версии реально запускаемых бинарников и явно отметить неподтверждённые возможности.

Пакет не подтверждает разрешение организаторов на конкретные подготовительные материалы. Он следует сообщённому вами ограничению: подготовка сетапа допустима, исходников продукта до старта быть не должно. При расхождении с официальным регламентом регламент имеет приоритет.

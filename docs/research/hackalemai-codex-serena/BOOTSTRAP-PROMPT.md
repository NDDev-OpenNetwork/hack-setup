# Задание агенту: настройка Codex + Serena-first для HackAlemAI

Ты настраиваешь среду разработки, а не реализуешь продукт хакатона. Прочитай этот файл, отчёт о совместимости, инструкции установки и приёмки до изменения конфигурации.

## Требования пользователя

Трое разработчиков работают только агентами в одном модульном монорепозитории. У каждого отдельная ветка и рабочая директория; интеграция идёт в `dev`, затем `main`. Разработка автономная, по небольшим законченным фичам. Приоритеты: скорость внедрения, работающий результат и согласованность кода. Не вводи тяжёлые обязательные пайплайны и подтверждения каждого редактирования.

Serena MCP используется первой для поддерживаемой семантической навигации и редактирования. Это не запрет текстовых инструментов: строки, конфигурация, документы и неподдерживаемые операции требуют подходящего инструмента. Проверяй фактически доступные возможности, не выдумывай инструменты и параметры.

Целевые машины: MacBook и VPS с 8 vCPU/32 GB RAM. Стек: Node LTS, Bun, нативный TypeScript, React/Vite/TanStack, Python/FastAPI, PostgreSQL, Qdrant, Redis, RustFS, Flutter/Dart, при необходимости Tauri/Rust/Go, Telegram, CLIProxyAPI/LiteLLM/OpenAI, OpenObserve/Vector/OTel, Docker Compose. Интерфейс RU/KK/EN. Для GPU возможно использование Modal. Каталог технологий не требует запускать все сервисы одновременно.

До начала хакатона нельзя создавать исходники продукта, бизнес-логику, готовые экраны или переиспользуемый каркас приложения. Сейчас разрешённый объём: настройка инструментов, инструкции, skills и документация. Держи подготовительные материалы вне конкурсного репозитория до момента, когда его метаданные разрешены. Синтетические проверки инструментов выполняй вне репозитория сдаваемого решения, не используй их как продуктовый код и соблюдай более строгие требования регламента, если они есть.

Не копируй секреты и значения ключей в отчёт. Определи фактическую разрешённую директорию настройки; не выдумывай адрес сервера или путь репозитория.
2. Сделай резервную копию только изменяемой конфигурации с сохранением прав доступа и обратимым diff. Сохрани рабочий provider, авторизацию, пользовательские инструкции, skills, rules и посторонние MCP. Устрани случайные дубли Serena, оставив одно намеренное подключение на сессию.
3. Зафиксируй проверенную базу либо отдельно обоснуй и проверь обновление. Serena: 1.7.0, commit `949a27ef1e5fda1a6e7b561e777bcece345c6ffd`; референс Codex: 0.155.1, commit `be2951ea34f0d295ed0becf97079f92fa5f6950e`. Исторический cutoff: 2026-09-19 23:59:59 Asia/Almaty (18:59:59 UTC). Установи Serena изолированным инструментом, не зависимостью FastAPI. Запиши фактические бинарники, версии, происхождение и разрешённые зависимости.
4. Подключи MCP к Codex с контекстом Serena `codex` и однозначным корнем worktree. Для каждого разработчика отдельный процесс Serena и собственное состояние активного проекта. Сервер должен видеть те же файлы, что агент. Настрой доверие конкретному проекту отдельно в Codex и Serena, без глобального wildcard-доверия.
5. Подготовь языковые серверы вне исходников продукта; включай только необходимые фактическому проекту языки. Один основной провайдер семантической навигации на язык. Различай компилятор проекта и движок LSP. До принятия дефолтов проверь исключения TypeScript, Dart, Python ty, Taplo и hooks.
6. Аккуратно добавь глобальные инструкции и установи библиотеку правил/skills в разрешённое место. Не считай произвольные Markdown-файлы или globs автоматически загружаемыми правилами Codex. Оставь короткий всегда загружаемый маршрутизатор. Вложенные AGENTS добавляй только в существующие директории и в разрешённый момент.
7. Lifecycle hooks включай после проверки их реального входа/выхода. Для Serena 1.7.0 не устанавливай `serena-hooks reset`. Не включай блокирующий `remind` по умолчанию. Дополнительное напоминание должно быть коротким, неблокирующим, не менять файлы и проверяться на настоящих событиях Codex.
8. Сохрани запрошенный автономный режим в уже разрешённой среде. Не вводи подтверждения обычных правок и проверок. Не расширяй молча доступ к посторонним машинам, аккаунтам, биллингу и production-ресурсам. Не смешивай несовместимые старую и новую модели permissions в конфигурации.
9. Выполни матрицу приёмки. Проверь настоящие определения, ссылки и изолированное переименование, а не только запуск процесса. Включи кириллицу/казахский текст, отдельные worktrees, видимость импортируемых generated-клиентов и отрицательные проверки форматов. Проверяй каждый доступный фактический целевой хост; недоступный не отмечай как проверенный.
10. Подготовь отчёт по машине, manifest версий/хешей, конфигурационный diff, измерения старта/ресурсов и оставшиеся ограничения. `PASS` ставь только с результатом выполненного инструмента или команды. Синтаксически корректный конфиг не является доказательством полной интеграции.

## Исправление проблем

Исправляй детерминированные ошибки среды самостоятельно. Для недоступной семантической операции используй узкий подходящий fallback и фиксируй ограничение. Не запускай бесконечные установки, перезапуски и полную переиндексацию. Не применяй force-install несовместимых зависимостей и не подавляй реальные ошибки глобально.

Не понижай продуктовый стек, чтобы скрыть старый адаптер LSP. Предлагаемый внешний адаптер SolidLSP становится работающей интеграцией только после установки и проверки. Согласованность Flutter и Dart проверяется по реально запущенному анализатору, не только по значению PATH.

## Результат

Верни изменённые подготовительные файлы и их расположение, реально выполненные команды, версии и хеши, заполненный отчёт и существенные блокеры. Не создавай продуктовый код. Закончи доступную локальную настройку в текущем выполнении; не обещай результат от будущей фоновой работы.


## Обязательные уточнения редакции 1.1

`base_modes` задавай в изолированном глобальном Serena-конфиге: в project.yml стабильного релиза этот ключ игнорируется. `project.local.yml` применяет поверхностную замену ключей, поэтому локальный словарь настроек LSP должен сохранять все нужные языки. Не коммить абсолютные пути машины.

Hooks необязательны. У Codex есть отдельное доверие к нормализованному определению hook; корректного JSON и включённой feature недостаточно. Не придумывай trusted_hash и не обходи доверие молча. SessionEnd ограничен тремя секундами. Конфигурируй доверие при подготовке, а не вводи подтверждения каждой фичи.

Новый механизм внешней регистрации LSP не входит в Serena 1.7.0. Любой переход на development commit или патч оформляй отдельно и проверяй, сохраняя реальную исходную идентичность. Не представляй установку LSP-бинарника как готовую интеграцию.

Проверяй исключения индекса по реальным authored-файлам, особенно директории build/dist/target. После timeout мутации сначала читай фактическое состояние, затем решай вопрос повтора. Команды проверки не должны молча форматировать, менять lockfiles, мигрировать БД или генерировать клиент. Два прохода одного агента не называй независимыми проверками.
